## 0. 一句话现状

引擎仍是 **Qwen3-TTS-12Hz-0.6B-Base**（起点）。追了 5 个替代候选全部被否。
**真正的收益不在换引擎，而在三件事**：调对了采样参数、缩短了分段、加上了自动质检门。

## 1. 已否决的候选（别再试了）

| 候选 | 否决原因 | 关键证据 |
|---|---|---|
| **Kokoro-82M**（audiblez 项目用的） | **不支持音色克隆**，只有固定音色 | 中文只有 8 个固定音色 `zf_*/zm_*`，无参考音频克隆能力；本项目整套参考音色资产会作废 |
| **IndexTTS-2.5**（本机 `IndexTTS/`，2026-08 版） | 未进入最终对比；用户此前反馈同类模型长文本表现差 | 单次克隆指标其实更高（0.794 vs Qwen3 0.724），但**单次指标测不出长文本稳定性** |
| **Fun-CosyVoice3-0.5B**（本机 `CosyVoice/`） | 同上；CosyVoice 系长文本口碑差 | 榜单中文困难集 CER：CosyVoice 一代 11.75% / 二代 6.83%（一代就是用户说的"灾难"） |
| **LongCat-AudioDiT-1B**（美团，2026-03） | **听感一票否决：电音严重** | 见第 2 节，指标曾显示四项全胜，被耳朵推翻 |
| **Qwen3-TTS-1.7B-Base** | 相似度反而更低，速度也没提升 | 同批 12 段：**0.7648 vs 0.6B 的 0.7779**；RTF 0.81 vs 0.84（批处理吃掉了参数量差异） |
| **VibeVoice-TTS**（微软，长文本 90 分钟） | **代码已被官方下架**（2025-09-05，因滥用），权重表标 `Disabled` | 现存的 VibeVoice-Realtime-0.5B 是**预设音色**，不支持任意参考克隆 |

**教训**：换引擎前先确认三件事——① 是否支持任意参考音频克隆；② 目标语言（中文）的社区实测口碑，不只看榜单；③ 官方仓库是否仍在维护（VibeVoice 就是查了才发现已下架）。

## 2. 最贵的一次翻车：LongCat 指标全胜但听感是"电音"

这是本次最值得记住的案例，因为它**暴露了指标体系的根本局限**。

### 2.1 指标说它全面更好

同批 12 个连续段落、同参考音频、同采样参数：

| 引擎 | 相似度↑ | 最低 | RTF↓ | CER↓ |
|---|---|---|---|---|
| Qwen3-0.6B（基准） | 0.7779 | 0.7514 | 0.84 | 10.65% |
| **LongCat-1B** | **0.8424** | **0.8252** | **0.25** | **9.94%** |

**相似度 12/12 段全胜，而且分布完全不重叠**（LongCat 最低 0.8252 > Qwen3 最高 0.807），速度快 3.3 倍。
我据此建议切换。**用户听完的反馈：电音有点严重，不如千问。**

### 2.2 真实原因：高频被过度谐波化

| 来源 | 6-9kHz 谱平坦度 |
|---|---|
| **真实人声**（参考音色原声 6 个片段） | **0.18 ~ 0.23** |
| Qwen3-0.6B 全章 526 段 | 0.052 ~ 0.156 |
| **LongCat-1B** | **0.023 ~ 0.032（人声的 1/7）** |

自然语音的 6-9kHz 含大量**非周期成分**（气声/齿音/摩擦音）。该频段被压成近乎纯谐波的周期性嗡鸣，听感就是"电音"。

**推测机理**：Wav-VAE 的潜帧率只有 **11.7 Hz**（压缩 >2000 倍，约 85ms 一帧），解码器要从极稀疏的 latent 里"脑补"全部细节。这也解释了美团论文里那句反直觉发现——"VAE 重建质量越好 ≠ TTS 生成越好"。

### 2.3 确认无法通过调参修复

改了扩散步数和引导方式，**完全没有影响**：

| 配置 | 6-9kHz 平坦度 | 耗时 |
|---|---|---|
| nfe=16（默认） | 0.0254 | 4.0s |
| nfe=32 | 0.0255 | 8.7s |
| nfe=64（4.6 倍算力） | 0.0265 | 18.5s |
| guidance 改 cfg | 0.0255 | 9.2s |
| 引导强度 4.0→2.0 | 0.0233 | 9.2s |

**结论：属模型固有特性，不用再花时间。**

### 2.4 由此得到了一个可用指标（已固化）

`quality.py::hf_tonality()` + `config.HF_TONALITY_MIN = 0.04`（另加 `>=3s` 时长门槛，短段方差大）。

门限依据 = 两侧几何中点：`(0.032 × 0.052)^0.5 ≈ 0.041`。
判别效果：**全章 526 段 0 误报，LongCat 12/12 全抓。**

**这是本次唯一"把听感变成可自动执行判据"的成果。** 以后换引擎/章节，这类缺陷不用靠耳朵。

## 3. 指标陷阱（我踩了三次，务必注意）

指标本身会骗人。以下三个坑都有实测支撑。

### 3.1 声纹相似度会被静音比例污染

同一段语音，**只是前后加静音**，相似度就变了：

```
原始 31.9s            sim = 0.7916
前后各加 2.0s 静音      sim = 0.8073   (+0.016)
前后各加 4.0s 静音      sim = 0.8135   (+0.022)
```

**加静音能"涨分"的量级，和一次真实音色改进（+0.024）一样大。**
→ 我据此错误地宣称过"新版音色 +0.0243"，实际去掉静音污染后**只有 +0.006**。

**正确做法**：声纹只统计**有声帧**（按帧能量做 VAD 后再过说话人模型），
并且锚点要独立于用来克隆的参考音频（用源音频里另一段台词，避免自己考自己）。

### 3.2 谱平坦度**不是越低越好**（方向性）

我第一次看到 LongCat 平坦度低 12 倍，读成"更干净"。
**因为从没量过真实人声的基准**——量了才知道方向是反的：自然语音高频本就含大量非周期成分，
**远低于人声 = 电音**。

**正确做法**：任何"越低越好/越高越好"的指标，都必须先量一个**真实人声基准**再解释方向。

### 3.3 绝对静音门限会被音量差异骗

用绝对门限（RMS < 0.005）统计静音比例时，两版音频音量差 2.8 倍（0.188 vs 0.068），
结果对旧版严重高估静音（38.5% vs 真实 34.8%），并让我得出"新版发声多了 9.2 分钟"的错误结论。
用**按段自适应门限**（`max(0.004, 12% × 该段90分位电平)`）后，真相是两者发声时长几乎一样。

### 3.4 全文检索式的教训

**用代理指标下结论前，先做"反事实实验"验证这个指标到底在测什么。**
比如"加静音看相似度变不变"——30 秒就能做的实验，我却在错了两次之后才做。

## 4. 一次判断错误：把"赶"归因于停顿太短

**过程**：换 `ref_tight` 后整章短了 26.8 分钟。我测出发声语速几乎不变（498→501 字/分钟），
但句间停顿中位数从 0.68s 掉到 0.40s，于是判断"停顿太短 → 赶"，
做了一套确定性分位数映射把停顿拉回 0.68s（`pacing.py`）。

**结果**：用户听完 v3 不满意。真正的主因是**段太长**（当时 205 字）。
**证据**：105 字分段 + 0.45s 段间静音、**完全不做停顿拉伸**的版本，被判定语速良好；
而停顿拉到 0.68s 的 v3 反而不满意。

**已处理**：`pacing.py` 及相关配置**已删除**（不是禁用，是删掉），避免以后有人以为它有用。

**教训**：听感问题别急着归因到单一可测量量。先做**消融对比**（只改一个变量，让用户听），
再决定往哪投入。我当时是先建了工具再找证据，顺序反了。

## 5. 真正有效的改动（都经过听感验证）

按收益排序：

| 改动 | 原值 → 新值 | 依据 |
|---|---|---|
| **分段长度** | 205 → **105** 字 | "赶"的真因；段短也不易漂移 |
| **段间静音** | 0.30 → **0.45** s | 配合上一条 |
| **采样参数** | 库默认 0.9/1.0/1.05 → **0.5/0.9/1.15** | 库默认是"追多样性"的探索配置，对"上千段要像同一个人"方向相反。实测 std 从 ±0.036 降到 ±0.011 |
| **`max_new_tokens`** | 1600 → **2048** | 原值**低于库默认**（2048），长段撞顶被截断 → 噪声尾。贪心解码实测能产出 163.8s 纯噪声（谱平坦度 0.353 vs 正常 0.014） |
| **参考音频** | `ref_clip_full.wav` → **`ref_tight.wav`** | 原来 8.60s 里只有 4.60s 真实语音、静音占 47%，且是三段独立台词拼接。ICL 克隆模式下模型直接以这段音频的 codec token 为条件 |
| **质检门**（新增） | 只有"时长≤60s" → 4 个信号 | 原判据抓不到"整段换人""局部换人""噪声退化""电音" |

### 参考音频的关键实测

| 文件 | 实际时长 | 真实语音 | 静音占比 |
|---|---|---|---|
| `ref_clip_30s.wav` | **8.00s**（不是 30s） | 4.35s | 46.8% |
| `ref_clip_53s.wav` | **8.00s**（不是 53s） | 3.10s | 61.8% |
| `ref_clip_full.wav` | 8.60s | **4.60s** | **47.0%** |

源文件 `ref_source_audio.m4a` 里有 **358 段干净台词、共 14 分多钟**，原先只用到了 4.6 秒。

**但注意**：参考音频不是越长越好。实测 10.64s 版本（多句拼接）**比 6.08s 版本更差**
（相似度 0.799 vs 0.830）。而且把参考里的停顿还原成 0.9s/1.4s 后，输出停顿只从 0.42s 回到 0.56s
——**映射非线性，靠改参考音频补不回节奏**。

## 6. 怎么评估一个新引擎（可复用流程）

**绝对不要**只跑一句话、或者只看榜单调参。Seed-TTS-eval 全部是**短句**指标，
**测不出长文本稳定性**——而这才是本项目的历史痛点。

### 标准流程

```powershell
# 1. 生成（envs\qwen3tts）；同批连续段落 + 同参考音频 + 同采样参数
python tts_eval\scripts\gen_qwen3.py --model-dir <模型目录> --out <名字>

# 2. 转写算 CER（envs\cosyvoice，有 whisper+opencc）
python tts_eval\scripts\transcribe.py --engines <名字>

# 3. 四维度打分
python tts_eval\scripts\score.py --engines <名字>

# 4. 逐句对照 + 连续试听文件
python tts_eval\scripts\persegment_and_listen.py

# 5. 电音专项
python tts_eval\scripts\buzz_diagnose.py
```

### 四个维度（缺一不可）

| 维度 | 工具 | 抓什么 |
|---|---|---|
| 音色相似度 | 有声帧 CAM++ 声纹 + **独立锚点** | 音色飘/换人 |
| 谱平坦度 | 只统计有声帧 | 噪声退化 |
| **6-9kHz 高频平坦度** | `hf_tonality()` | **电音** |
| 停顿节奏 | 按段自适应门限 | 语速/停顿 |
| **CER（whisper 转写对比原文）** | `transcribe_dir.py` | **漏字/重复/错读** |

**CER 的噪声底要先标定**：用**已知文本的真实人声**过同一个 whisper。
实测参考音色原声 **CER = 0.00%**，所以 ~10% 的合成 CER 是真实误差，不是测量噪声。
另外**必须同时看"转写长度/原文长度"比值**，才能区分"读错字"和"漏内容"。

### 判定标准（实测值，可作参照）

| 指标 | 人声基准 | 本项目基准 | 危险区 |
|---|---|---|---|
| 声纹相似度（独立锚点） | – | 0.778 | < 0.62（旧章最低 0.663） |
| 6-9kHz 平坦度 | 0.18~0.23 | 0.113（最低 0.052） | < 0.04（LongCat 0.027） |
| CER | 0.00% | 9.65% | > 15%（F5-TTS 中文 15.5%） |
| 长度比 | 1.00 | 0.997 | < 0.9 需单独查 |

### 最后一道关：**必须让人听**

LongCat 的案例证明：**指标能排除坏的，但不能替代耳朵判定"好听"。**
指标全胜的候选，照样可能被一句"电音"否掉。所以流程是：
**指标筛掉明显不合格的 → 剩下的做成连续试听文件 → 人听 → 再决定。**

试听文件做法：同一批 12 段按相同顺序拼接成一个 wav（段间 0.45s），
外加逐句三连对照（`cmp_segNN.wav`）。**别让人去点十几个小文件听。**

## 7. 环境坑（会直接卡住进度）

| 坑 | 现象 | 解法 |
|---|---|---|
| **huggingface.co 不可达** | 连接被关闭；`hf download` 失败 | 用 **ModelScope**（`snapshot_download`）；或设 `HF_ENDPOINT=https://hf-mirror.com`（本机实测通） |
| **LongCat 需要 `transformers>=5.3`** | `ImportError: cannot import name 'PreTrainedConfig'`（本机 qwen3tts 是 4.57.3） | 建**独立 venv**，别升级现有环境 |
| **`venv --system-site-packages` 不继承父 venv** | 新建 venv 里 `No module named 'torch'`——它继承的是**基础 Python**，不是 qwen3tts 这个 venv | 在该 venv 的 site-packages 放一个 `.pth` 文件，内容为父 venv 的 site-packages 路径 |
| **ffmpeg 无 `libfdk_aac`** | audiblez 的 m4b 代码直接报错（非自由编码器，多数构建不带） | 改用原生 `-c:a aac` |
| **Windows subprocess 读中文输出** | `UnicodeDecodeError: 'gbk' codec can't decode` | 所有 `subprocess.run(text=True)` 加 `encoding='utf-8', errors='replace'` |
| **章名与序号错开一位**（本项目的坑） | 「第六章」的文件前缀是 `ch07`；「第七章」是 `ch08` | 沟通时**明确说"序号N"还是"章名"** |

## 10. 已知未完成

1. **全书未统一**：序号 1–6（序 + 第一~五章）仍是旧的 205 字 / temp0.9 / ref_clip_full 版本。
   按实测 14.6 秒/段，全量重做约 **13 小时**（3232 段）。
   更省的做法：先跑 `voice_quality_audit.py` 扫旧章，只重做不合格的段。
2. **长文本稳定性只验证到单章**（526 段 / 143 分钟，相似度均值 0.778 与 12 段基准差 0.0001）。
   跨章一致性未验证。
3. **CER 9.65% 基本全是同音字混淆**（亭阁→停格、篝火→勾火、赤道浅海→吃到前海、迈克→麦克），
   **不是漏字或重复**（526 段里仅 1 段长度比 < 0.9）。
   若要降 CER，方向是**用 IndexTTS-2.5 的拼音控制**修多音字，而不是换引擎。

## 11. 用 Web UI 重跑（本次为它做的修复）

### 11.1 已修复：chunk 缓存的段号错位（这是个真 bug）

**问题**：`engine.synthesize_book`（UI 走的就是它）原来**无条件复用** `_chunks/` 里的旧段。
段级缓存是按「段号」命名的——分段长度从 205 字改成 105 字后，**同一段号对应的文本完全不同**，
复用就会拿 A 的音频配 B 的文本。

**实测的真实案例**：《海伯利安的隕落》旧状态里 ch25 残留 12 个旧段（205 字口径），
而 105 字口径该章需要 84 段 → 段号 0~11 全部错位。

**修复**：新增 `engine.chunk_cache_key()`，把
`分段长度 + 参考音频(名字+大小) + temperature + top_p + repetition_penalty + max_new_tokens`
算成一个指纹写进 `task_state.json`。**指纹不一致时拒绝复用旧段并告警**：

```
!! chunk 缓存指纹变化 c105_ref_tight_6c82be -> c55_ref_tight_e0f7c9：
   分段长度/参考音色/采样参数已变更，旧段不再复用，将重新生成
```

**副作用（符合预期）**：用旧版本生成过的书，其 `task_state.json` 里没有 `chunk_key`，
再次运行时指纹视为不一致 → **不会复用旧段**（安全侧）。

### 11.2 每次生成会打印生效配置

### 11.3 ⚠️ 重跑合集时**必须手动只勾一本**

「生成书」页的分册勾选框**默认全选**。合集 epub 解析出 5 册：

| 分册 | 字数 | 105字段数 | 状态 |
|---|---|---|---|
| 海伯利安 | 336,471 | ~3,780 | 已完成（旧方法） |
| 海伯利安的隕落 | 375,386 | ~4,220 | 已清空，待重跑 |
| 安迪密恩 | 393,503 | ~4,420 | 未开始 |
| 安迪密恩的覺醒 | 531,784 | ~5,980 | 未开始 |
| 螺旋的遺孤 | 36,777 | ~410 | 未开始 |

**若直接点「开始生成」而不取消勾选**，会把后 4 本一次性排上（约 15,000 段 ≈ 60 小时）。
**务必只保留「海伯利安的隕落」一项。**

（顺带：代码里 `wanted` 为空时**不做过滤**，等于"全选"——所以"一个都不勾"更危险，别用。）
