## 1. 一分钟理解这个项目

**做什么**：把一本电子书批量转成有声书，**克隆一个指定的音色**，全本地运行。

**技术栈**：Qwen3-TTS-12Hz-0.6B-Base（`qwen_tts` 0.1.1）+ CAM++ 声纹质检 + ffmpeg。
界面是 Gradio Web UI，模型跑在 CUDA 上。

**核心设计**：把书切成 ~105 字的**段**，逐段用参考音频做 ICL 音色克隆合成，
**每段生成后过一道质检门**（像不像参考音色 / 有没有退化 / 有没有电音），
不合格就重生成；段级缓存落盘，因此可以随时中断、断点续跑；最后按章拼接成 mp3。

**这个项目真正的价值不在"调用了哪个 TTS"**，而在四件事：
1. **段级质检门**——把"音色飘 / 杂音 / 电音"变成可自动执行的判据
2. **调对了采样参数**——库默认参数对"上千段要像同一个人"是反向的
3. **分段长度**——听感"赶"的真正原因
4. **一套可复现的引擎评测方法 + 一整套已排除的选项**（`tts_eval/README.md`）

## 2. 架构与调用链

```
start_ui.ps1
  └─ app.py                      Gradio UI（两个页签：生成书 / 书库）
       ├─ ebook.parse_books()    解析 → (合集名, [ {title, chapters:[{index,title,text}]} ])
       └─ _run() → engine.synthesize_book(book_dir, chapters, ref_audio, ref_text, ...)
            ├─ engine.get_model()              加载 Qwen3TTSModel（单例）
            ├─ engine.set_reference()          设置参考音频 + ref_text（ICL 克隆 prompt）
            ├─ engine.get_gate(ref)            quality.SegmentGate（按参考音频路径缓存）
            ├─ engine.split_segments(text)     按标点切段，≤105 字
            ├─ engine._gen_guarded_v2()        批量生成 → 逐段质检 → 不合格重生成
            ├─ quality.SegmentGate.check()     四个信号
            └─ 拼接（段间 0.45s 静音）→ 写章 mp3 → 全书 mp3 + m3u
```

### 各文件职责

| 文件 | 职责 | 改动风险 |
|---|---|---|
| `config.py` | 所有参数与路径解析。**证据都写在注释里** | 低（改参数） |
| `engine.py` | 模型加载、分段、批量生成、质检门接线、拼接、状态机 | **高（核心）** |
| `quality.py` | CAM++ 声纹 + 谱平坦度 + 6-9kHz 电音指标 + `SegmentGate` | 中 |
| `ebook.py` | EPUB（合集/单本）/MOBI/TXT 解析、章节标题提取、噪声页过滤 | 中 |
| `text_clean.py` | 正文清洗（去页眉页脚、合并断行、全半角等） | 低 |
| `app.py` | UI。**不含生成逻辑**，只做参数收集与进度展示 | 中 |

### 关键函数（`engine.py`）

```python
split_segments(text, max_chars=config.MAX_CHARS_PER_SEG) -> list[str]
    # 按句末标点切段并合并到 ≤max_chars。刻意不切断句子。
    # ⚠ 因此单句 >max_chars 时该段会超长（实测出现过 1 段 = 3083 字的整章）

_gen_kwargs() -> dict          # 采样参数（temp/top_p/rep）
_gen_one(model, prompt, text)  # 单段生成
_gen_guarded_v2(model, prompt, seg, gate)   # 段生成 + 质检 + 重生成（最多 GATE_MAX_ATTEMPTS 次）
get_gate(ref_audio)            # 取/建质检门（按参考音频路径缓存，避免重复加载 onnx）
chunk_cache_key(ref_audio)     # ★ chunk 缓存指纹，见第 5.2 节
synthesize_book(book_dir, chapters, ref_audio=None, ref_text=None,
                stop_event=None, progress_cb=None, collection='', book_title=None)
    # 返回 (全书 mp3 路径, state)。断点续跑；已完成的章跳过。
```

## 3. 数据契约

### 3.1 `parse_books` 的返回

```python
name, books = ebook.parse_books(path)
# name  : str  合集名（单本书时 = 文件名）
# books : list[{ "title": str, "chapters": [ {"index": 1-based, "title": str, "text": str}, ... ] }]
#         单本书时 len(books) == 1
```

`app.py` 按 `books` 的条目生成勾选框；**用户勾选后逐本调用 `synthesize_book`**。

### 3.2 书目录

```
output\<书名>\
  task_state.json     进度状态（见下）
  _chapters.json      章节文本快照 [{"index","title","text"}]（续跑时不必重解析电子书）
  _chunks\            段级缓存 <safe_book>_chNN_segNNNNN.wav
  <书名>_chNN_<章名>.mp3
  <书名>_全书.mp3
  <书名>_播放清单.m3u
```

### 3.3 `task_state.json`

```json
{
  "book": "海伯利安的隕落",
  "collection": "海伯利安四部曲(...)",
  "created": "2026-09-13 17:48:09",
  "status": "running | paused | done",
  "config": {
    "ref_audio": "...ref_tight.wav",
    "ref_text": "<与参考音频逐字一致的文本，由使用者提供>",
    "chunk_key": "c105_ref_tight_6c82be",     // ★ 缓存指纹
    "max_chars": 105,
    "batch_size": 4
  },
  "chapters": [
    {"index":1,"title":"第一部·01","chars":4934,"segs_total":27,"done":true,"mp3":"...mp3"}
  ]
}
```

**状态机**：`running` →（停止）`paused` →（继续）`running` →（全部章完成）`done`。
`app.py` 的书库页以 `status == 'done'` 判断是否已完成。

### 3.4 段缓存命名

`<safe_book>_ch{index:02d}_seg{seg_index:05d}.wav`，`safe_book = engine.safe_name(书名)`
（把 `\ / : * ? " < > |` 和空白替换/压缩，截断 60 字）。

**段号是「当前 `MAX_CHARS_PER_SEG` 口径下的序号」**——这就是为什么必须有指纹机制。

### 3.5 ⚠️ 切分算法变更必须递增 `SEG_VERSION`

`config.SEG_VERSION` 会被算进段缓存指纹（`chunk_cache_key`）。
**任何切分逻辑的改动都要 +1**，否则"上限没变但算法变了"会导致旧段被静默复用、
音频与文本错位——与 205→105 那次是同一类 bug。

| 版本 | 说明 |
|---|---|
| v1 | 原实现：二级切分（`，、：`）**只在首段生效**；标点集合只有中文标点 |
| **v2** | 原子片段 + 贪心合并；标点扩展（`/ \ ＞ ][` 等排版符）；**强制切分兜底** |

**v1 的真实故障**（《海伯利安的隕落》ch33）：原文有一段机器独白的"咏唱体"，
用 `/` `\` `＞` `][` 当分隔符、**一个中文标点都没有**（1092 字里句末标点 1 个、逗号 0 个）。
v1 切不开 → 单段 1092 字 → 生成 **163.8 秒**（`163.8 × 12.5Hz = 2047.5 ≈ MAX_NEW_TOKENS 2048`）
→ **撞 token 上限被截断** → 残余挤成一个 8 字的垃圾段（`][喝！][喝！`，声纹相似度 0.176）。

**v2 的效果**（全书 375,386 字实测）：段数 4,232 → 4,276（**仅 +1.04%**），
最长段 1,301 → **105 字**，超过 105 字的段 95 → **0**，仅 12/46 章段数有变化。

**推论（写给接手的人）**：任何"文本里可能不出现常规标点"的来源都要假设它存在。
`_hard_split()` 的兜底不是可选项——去掉它就会重现上面这条故障链。

### 3.6 现有切分的已知局限（多角色前必须解决）

**42% 的段跨越说话人边界**（实测 1,776/4,232 段同时含旁白与对话），
这类段**物理上无法分配单一音色**。所以多角色的前提是改为
「按说话人轮次切分 + 按音色合并」（见第 10 节未完成项）。

另外，现有切分会在引号中间断开（例：段 N 以 `「正是在下。` 结尾、段 N+1 以 `」我撒了谎` 开头）——
对单音色无害（TTS 忽略引号），但多角色必须做到引号感知切分。

## 4. 当前采纳的配方（有实测依据，改动前请看依据）

| 参数 | 值 | 依据（详见 `config.py` 注释） |
|---|---|---|
| 模型 | `Qwen3-TTS-12Hz-0.6B-Base` | 1.7B 版相似度反而更低（0.7648 vs 0.7779） |
| `MAX_CHARS_PER_SEG` | **105** | 205 字时听感"赶"；105 字被判定语速良好 |
| `SEG_VERSION` | **2** | 切分算法版本；改动切分逻辑必须 +1（见 3.5） |
| `SEG_SILENCE_SEC` | **0.45** | 配合上一条 |
| `TEMPERATURE` | **0.5** | 库默认 0.9 会让 std 从 ±0.011 涨到 ±0.036 |
| `TOP_P` | **0.9** | |
| `REPETITION_PENALTY` | **1.15** | 库默认 1.05 |
| `MAX_NEW_TOKENS` | **2048** | 原值 1600 低于库默认，长段撞顶被截断 → 噪声尾 |
| 参考音频 | `ref_tight.wav`(6.08s) | 原 `ref_clip_full.wav` 静音占 47%、三段拼接 |
| 克隆模式 | `x_vector_only_mode=False` | ICL 克隆（用参考音频的 codec token 作条件），音色更稳 |
| 停顿拉伸 | **无**（曾是 `pacing.py`，已删除） | "赶"的真因是段太长，不是停顿太短——见 `tts_eval/README.md` 第 4 节 |

### 全章实测（第六章 526 段 / 143.0 分钟，作为回归基准）

| 指标 | 值 |
|---|---|
| 声纹相似度（独立锚点） | 均值 **0.7778**，std 0.0202，最低 0.6927 |
| 6-9kHz 电音指标 | 均值 0.1134，最低 0.0516（门限 0.04） |
| 段内停顿中位 | 0.400s |
| **质检门不合格** | **0 / 526** |
| **重生成次数** | **0**（两半各 263 段） |
| CER（whisper small 转写对比原文） | 均值 9.65%，中位 9.09%，最大 23.40% |
| 转写长度 / 原文长度 | 0.997；仅 1/526 段 < 0.9 |

**12 段基线与 526 段全章的相似度均值只差 0.0001** → 说明长文本稳定性没问题，
可以用小批量做回归。

## 5. 必须遵守的不变量

> 这几条都是**踩过坑之后立的**。改动它们前请先读 `tts_eval/README.md` 对应章节。

### 5.1 分段长度变了，段缓存必须全部失效

段缓存按**段号**命名。`MAX_CHARS_PER_SEG` 从 205 改成 105 后，
**同一段号对应的文本完全不同** → 复用旧段 = 拿 A 的音频配 B 的文本。

**这是真实发生过的 bug**：《海伯利安的隕落》ch25 残留 12 个 205 字口径的段，
而 105 字口径该章需要 84 段，段号 0~11 全部错位。

### 5.2 `chunk_cache_key` 机制（不要绕过它）

`synthesize_book` 会把
`分段长度 + 参考音频(名字+字节数) + temperature + top_p + repetition_penalty + max_new_tokens`
算成指纹写进 `task_state.json` 的 `config.chunk_key`。

- 指纹**一致**才复用 `_chunks\` 里的旧段
- 指纹**不一致**就打印告警、拒绝复用、全部重新生成
- 旧版状态文件没有 `chunk_key` → 视为不一致（安全侧）

**任何影响「文本→音频」对应关系的参数，都必须进指纹。**
要加新参数（比如换采样率、加 seed）时，记得同步更新 `chunk_cache_key()`。

回归测试：`scripts/test_ui_path.py`

### 5.3 段间静音只在"最终拼接"时加入

`SEG_SILENCE_SEC` 是拼接阶段填的，**不是写进段 wav**。
因此段 wav 是纯净的，可以自由重组/重拼。

### 5.4 质检门的朝向（四个信号的方向不能搞反）

| 信号 | 方向 | 门限 | 含义 |
|---|---|---|---|
| `sim` 整体声纹相似度 | **越高越好** | ≥ 0.62 | 越低越"不是这个人" |
| `win_sim` 3s 滑窗最低相似度 | **越高越好** | ≥ 0.45 | 抓局部换人 |
| `flatness` 谱平坦度 | **越低越好** | ≤ 0.08 | 越高越是噪声 |
| `hf_tonality` 6-9kHz 平坦度 | **越高越好** | ≥ 0.04 | **越低越"电音"** ← 最容易读反 |

`hf_tonality` 是唯一一个"越低越糟"的高频指标。**自然语音在 6-9kHz 有大量非周期成分**
（气声/齿音/摩擦音），被过度谐波化后该值会塌到人声的 1/7，听感就是电音。
标定：真实人声 0.18~0.23；本项目 526 段最低 0.0516；LongCat 0.023~0.032 → 取 0.04。

**不要把 `HF_TONALITY_MIN` 调低来"减少重生成"**——那会让电音漏过去。

### 5.5 声纹相似度必须用**有声帧**统计

静音比例会污染相似度：同一段语音**只是前后各加 2s 静音**，相似度从 0.7916 涨到 0.8073。
加静音能"涨分"的量级（+0.016~0.022）和一次真实音色改进（+0.024）同量级。

- `quality.py` 的 VAD 稳健路径：先按帧能量筛有声帧再提声纹
- 评测时必须用**独立锚点**（源音频里另一段台词），不要用被克隆的那段参考音频（自己考自己）

### 5.6 噪声页过滤的**顺序**不能反

`ebook._filter_chapters()` 里：
```
① 先用正文首行修正"文件名式"占位标题（part0065.html → "图书在版编目（CIP）数据"）
② 再判纯符号标题
③ 再做噪声关键词 / 目录页判定
```
**先判定后改名 = 永远识别不出这些页。** 这是《银河帝国》那本书暴露出来的：
15 个 CIP 页、11 个二维码推广页的标题在过滤时都还是 `partNNNN`，全部漏过。

### 5.7 EPUB 解析的两条路径

- `_parse_epub_books()`：合集。**方案 A** 嵌套 NCX（顶层项带子节点，如海伯利安四部曲）；
  **方案 B** 扁平 NCX（顶层项都无子节点、只是各册起始位置，如银河帝国 15 册）。
  方案 B 要求**每一段 ≥ `MIN_VOLUME_CHARS`(20000) 字**才认定为合集——
  这是为了区分"15 个顶层项 = 15 本书"和"40 个顶层项 = 一本小说的 40 章"。
- `_parse_epub()`：单本。
- `_guess_title()` 的占位值黑名单（`_PLACEHOLDER_TITLES`）**必须包含 `unknown`**：
  这个 EPUB 有 436 个文件写 `<title>Unknown</title>`，旧代码只挡了 `untitled`，
  于是直接返回 "Unknown" 并提前结束，**永远看不到正文里真正的 h3/h4 标题**。

回归测试：`scripts/verify_parse.py`（同时校验银河帝国 15 册与海伯利安四部曲 5 册）

### 5.8 参考音频质量决定上限

- 只要**一段连续语音**；多句拼接会变差（实测 10.64s 拼接版 0.799 < 6.08s 单段版 0.830）
- **必须先剪静音**（原参考 8.60s 里只有 4.60s 真实语音、静音 47%）
- 尝试用"把参考音频里的停顿还原"来修节奏是**无效的**：
  参考停顿 0.9s/1.4s 时输出停顿只从 0.42s 回到 0.56s，映射非线性

## 6. 环境事实（别浪费时间重新发现）

| 项 | 事实 |
|---|---|
| 网络 | **`huggingface.co` 不可达**；`hf-mirror.com` 和 `modelscope.cn` 可用 → 一律走 ModelScope |
| `transformers` | **必须 4.57.3**（`qwen_tts 0.1.1` 强依赖）。5.x 是为 LongCat 那类新模型准备的，本项目不用 |
| Python | 3.12.10 验证通过 |
| torch | 2.13.0+cu126 / torchaudio 2.11.0+cu126 |
| ffmpeg | 需要，且要有 `libmp3lame`。**`libfdk_aac` 通常没有**（非自由编码器）→ 不要用 audiblez 那套 m4b 代码 |
| 模型目录结构 | 库在**没有 `generate_config.json`** 时用硬默认参数（`do_sample=True, top_k=50, top_p=1.0, temperature=0.9, repetition_penalty=1.05, max_new_tokens=2048`）——本项目靠显式传参覆盖 |
| Windows 坑 | `subprocess` 读中文输出必须 `encoding='utf-8', errors='replace'`，否则 GBK 解码崩溃 |
| venv 坑 | `venv --system-site-packages` 继承的是**基础 Python**，不是父 venv。要复用父 venv 得放 `.pth` 文件指向它的 site-packages |
| 显存 | 0.6B 模型 + 质检门，6GB 够用；`BATCH_SIZE=4` |

## 7. 怎么评估一个新引擎（照做，别自创）

> **绝对不要**只跑一句话、或只看榜单调参。
> Seed-TTS-eval 那些榜单**全是短句指标，测不出长文本稳定性**——而那正是本项目的历史痛点。

### 7.1 标准流程

```powershell
# 0. 准备 12 段共享测试样本（同一批连续段落，105 字口径）
python tts_eval\scripts\make_segments.py

# 1. 生成：同一批段 + 同一参考音频 + 同一采样参数，只换引擎
python tts_eval\scripts\gen_qwen3.py --model-dir <模型目录> --out <引擎名>

# 2. 转写算 CER（需要 whisper；用独立 venv 或装 openai-whisper + opencc）
python tts_eval\scripts\transcribe.py --engines <引擎名>

# 3. 四维度打分
python tts_eval\scripts\score.py --engines <引擎名>

# 4. 逐句对照 + 连续试听文件（★ 人耳这一步不能省）
python tts_eval\scripts\persegment_and_listen.py

# 5. 电音专项
python tts_eval\scripts\buzz_diagnose.py
```

### 7.2 四个维度（缺一不可）

| 维度 | 抓什么 |
|---|---|
| 声纹相似度（有声帧 + 独立锚点） | 音色飘 / 换人 |
| 谱平坦度（有声帧） | 噪声退化 |
| **6-9kHz 高频谱平坦度** | **电音** |
| CER + 长度比 | 漏字 / 重复 / 错读 |
| 段内停顿中位 | 语速节奏 |

### 7.3 CER 的噪声底必须先标定

用**已知文本的真实人声**过同一个 whisper。实测参考音色原声 **CER = 0.00%**，
所以 ~10% 的合成 CER 是真实误差，不是测量噪声。
**必须同时看「转写长度/原文长度」**，才能区分"读错字"和"漏内容"。

### 7.4 判定阈值（实测值，可作参照）

| 指标 | 真实人声 | 本项目基准 | 危险区 |
|---|---|---|---|
| 声纹相似度（独立锚点） | — | 0.778 | < 0.62（旧章最低 0.663） |
| 6-9kHz 平坦度 | **0.18~0.23** | 0.113（最低 0.052） | < 0.04（LongCat 0.027） |
| CER | **0.00%** | 9.65% | > 15% |
| 长度比 | 1.00 | 0.997 | < 0.9 需单独查 |

### 7.5 最后一道关：必须让人听

LongCat 的案例证明：**指标能排除坏的，但不能替代耳朵判定"好听"。**
指标四项全胜的候选，被一句"电音有点严重"否掉。
所以流程是：**指标筛掉明显不合格的 → 做成连续试听文件 → 人听 → 再决定。**

试听文件做法：12 段按相同顺序拼成一个 wav（段间 0.45s）+ 逐句三连对照。
**别让人去点十几个小文件听。**

## 9. 指标陷阱（这个项目最贵的教训，务必牢记）

### 9.1 声纹相似度会被静音比例污染

```
原始 31.9s           sim = 0.7916
前后各加 2.0s 静音     sim = 0.8073   (+0.016)
前后各加 4.0s 静音     sim = 0.8135   (+0.022)
```
**加静音能涨的分，和一次真实音色改进一样大。**
我据此错误宣称过"新版音色 +0.0243"，去掉静音污染后**实际只有 +0.006**。

→ 只统计**有声帧**；锚点必须**独立于**被克隆的参考音频。

### 9.2 谱平坦度**不是越低越好**（方向性）

我曾看到 LongCat 平坦度低 12 倍，读成"更干净"——**因为从没量过真实人声的基准**。
量了才知道方向是反的：自然语音高频本就含大量非周期成分，**远低于人声 = 电音**。

→ 任何"越低越好/越高越好"的指标，都必须**先量真实人声基准再解释方向**。

### 9.3 绝对静音门限会被音量差异骗

用固定门限（RMS < 0.005）统计静音比例时，两版音频音量差 2.8 倍（0.188 vs 0.068），
对旧版严重高估静音（38.5% vs 真实 34.8%），据此得出"新版发声多了 9.2 分钟"的错误结论。

→ 用**按段自适应门限**：`max(0.004, 0.12 × 该段 90 分位电平)`，停顿 ≥0.25s 才算。

### 9.4 方法论

**用代理指标下结论前，先做"反事实实验"验证这个指标到底在测什么。**
比如"给音频加静音看相似度变不变"——30 秒就能做，我却在错两次之后才做。

## 12. 想扩展时怎么做

**加一个 UI 功能**：`app.py` 只负责收集参数与展示，生成逻辑一律加到 `engine.py`。
不要在 `app.py` 里复制生成代码——历史上就是这么产生分叉的。

**改动生成参数**：改 `config.py`，**并在注释里写实测依据**（这是本项目的惯例，
`config.py` 和 `tts_eval/README.md` 就是靠这个才没丢失结论）。
改完务必确认 `chunk_cache_key()` 能感知到你的新参数。

**新增质检信号**：加在 `quality.py::SegmentGate.check()`，门限放 `config.py`，
并**在两个方向上标定**：① 真实人声/已知良好样本上的分布 ② 已知坏样本上能否抓到。
只测"能抓到坏的"会导致大量误报（本项目踩过：门限定错时 526 段里误报过）。

**换参考音色**：先在 `tts_eval` 里做 12 段对照（新参考 vs 旧参考），
看相似度、电音指标、停顿中位数，再听。**不要只凭单段试听就换。**
